# 行意 · 买卖匹配与线索处理

[在线体验](https://intent-car-agent.youngcoin22.chatgpt.site) · [源码](https://github.com/wittlud7/used-car-growth-agent) · [发布边界与简历表述](docs/发布说明.md)

基于 DeepSeek 工具调用的独立个人作品。模型理解需求、调用车源/买家查询工具，程序核验证据与条件，人工确认跟进。**全部车源和初始咨询为合成数据，未接入瓜子内部系统。**

线上版支持真实 Agent、多轮需求、对比、待办确认、批量咨询及实测对照；Python 本地完整版另有后台批次、咨询审核和跟进状态管理。两版功能差异、访客数据与额度见 [发布说明](docs/发布说明.md)。

验证：68项 Python 离线测试、8项线上工具测试，以及构建后的HTTP访客隔离验证。公开对照中，直接模型与Agent方案均6/6通过，直接模型更快且消耗更少；不据此宣称准确率提升或成交收益。

## v0.5：批量咨询处理与实测对照

左侧“咨询自动处理”支持每行一条咨询、JSON/CSV导入，或选择咨询管理中已有的1至20条。可选真实DeepSeek Agent或离线规则演练。后端逐条运行，记录需求证据、实际工具、候选和下一步：匹配、追问、无匹配、人工复核、停止/暂缓跟进、失败。

补充客户信息会创建关联批次，保留旧记录；Agent模式沿用原对话，条件变化后重查。人工结果与实际处理秒数单独留痕。结果登记属于本批次记录，不会自动推进咨询管理中的审核状态，也不会发送消息或预约。批次输入不会自动变成卖车工具的买家库，买家工具仍读取“咨询管理”；正式联通CRM及统一客户身份是后续工作。

批次运行不依赖浏览器页面保持打开；刷新可恢复。可停止后续调用，当前在途请求完成后停止。服务重启时，未完成批次标记中断，不偷偷重试产生额外API用量。相同批次内相同姓名/来源/原文自动去重；重新提交会保留新的运行记录。全局仅允许一个批次运行。

“运行两组对照”用6条公开、人工标注的合成验收案例。直接问模型获得相同业务政策和完整车源快照，无工具与后置业务校验；Agent组使用真实工具与程序校验。评估结构化分流与候选集合，不评估所有自然语言表述。部分拦截不调用模型，这计入方案差异。模型输入不含正确答案，不人为构造直接模型的失败。

本次真实结果：两组均6/6通过，错误推荐及候选遗漏均为0；直接模型平均约0.93秒、8587 tokens，Agent组平均约2.37秒、18387 tokens。小样本不证明Agent准确率更高，单轮查询直接调用更省。项目展示的增量是批处理、可核验约束、持续对话、人工接手和操作记录。原始结果：`output/workflow-live-benchmark.json`。人工节省时间、成交提升及人民币成本没有测量或价格配置，不提供虚构数值。

核心模块：`workflow.py`（持久化后台批次、分流、对照与结果登记），`web/workflow.js` / `workflow.css`（工作台）。配置与密钥继续只在服务端读取。

离线验证：`python -m unittest discover -s tests -v`。`tests/browser-workflow.js` 验证批次、拒绝联系保护、人工记录、补充需求、刷新和移动端。`python tests/live_workflow_smoke.py` 显式调用8766的独立QA服务和真实API，消耗模型用量，覆盖卖车匹配与买车补充预算后的同会话重查。

## v0.4：真实 DeepSeek Agent

默认首页是“Agent 对话”。模型根据上下文决定追问还是调用工具，不再只依赖表单固定执行。

- 支持多轮需求补充、中文数字预算、查询车源、车辆对比、查找买家、生成待办确认卡。
- 工具：`read_requirements`、`list_models`、`update_requirements`、`search_vehicles`、`find_buyers`、`compare_vehicles`、`propose_task`。
- 初次补录允许引用历史用户原文；修改已有预算、城市等条件必须引用当前用户消息。数值及原文引用由服务端核验。无结果不自动放宽条件。
- 模型只能生成确认卡；用户点击“核对并确认”、补充负责人后，才由独立HTTP接口创建本地待办。更改条件会使旧确认卡失效，重复确认不会重复创建。
- 界面展示真实模型回复、实际工具参数/结果和API返回的token用量；不展示模型思维链。失败明确标记，不冒充规则回退为模型成功。
- 对话、条件、工具记录及确认卡保存在SQLite，刷新可恢复，也纳入“导出记录”。

### 本机 DeepSeek 配置

服务端默认读取项目父目录的 `settings.json`，或环境变量 `AGENT_SETTINGS_FILE` 指定的路径。仅使用 `env.ANTHROPIC_AUTH_TOKEN`、`env.ANTHROPIC_BASE_URL`、`env.ANTHROPIC_MODEL`；不将文件里的CLI权限设置当作应用指令。

当前配置的 `/anthropic` 地址在服务端规范化为 DeepSeek `/chat/completions` 地址；保留文件中的 `deepseek-v4-flash` 名称。密钥不复制进项目、不返回浏览器、不写入日志或对话。已有环境变量 `AGENT_API_KEY` / `AGENT_MODEL` / `AGENT_API_BASE` 可以覆盖本地配置。

真实连接与工具流程已验证，结果保存在 `output/live-agent-smoke.json`。车源和初始买家仍为模拟数据，没有接入真实交易系统。

官方协议参考：[DeepSeek 工具调用](https://api-docs.deepseek.com/guides/tool_calls/)、[对话接口](https://api-docs.deepseek.com/api/create-chat-completion/)。本实现使用非思考模式运行工具循环，避免保存模型思维链。

验证命令：`python -m unittest discover -s tests -v`（不进行真实API调用）；`python tests/live_agent_smoke.py`（显式进行真实API验证，使用独立合成数据库并消耗API用量）。浏览器真实API验收脚本为 `tests/browser-agent-live.js`，请只对独立且未建立待办的测试数据库运行。

## v0.3：从匹配到待办

- 买车结果最多勾选3辆并排对比价格、上牌年份、里程、城市、车身和能源；可以建立本地看车待办，填写客户、负责人、期望时间和备注。
- 卖车结果可以建立买家跟进待办；必须先审核通过买家咨询，才能确认跟进。人工登记“已联系”后，同步原咨询状态和来源统计。
- 在“跟进队列”统一确认、完成或取消待办。状态为待确认→已确认→已完成/已取消，带操作记录及版本检查。
- 同一匹配、同一候选项重复建单不会重复插入；建立和确认时复查当前资格，已售车辆、拒绝联系或结束的买家不会继续进入确认流程。
- 待办是本地记录，不代表已向车商预约，也不会发送客户消息。卖车联系结果必须由人登记。
- 全部43项测试通过；`tests/browser-tasks.js` 在独立、初始未审核的测试数据库验证对比、待办、审核及联系结果同步。测试脚本会修改模拟数据，请勿对正式演示库运行。

## v0.2：买车 / 卖车

首页改为买卖匹配，移除宣传句和大段说明。

- **买车**：按城市、预算区间、车型或品牌、车身/能源类型、最早上牌年份、最高里程匹配模拟车源。只返回在售车辆；异地需主动勾选。无结果时不自动放宽条件。
- **卖车**：填写车辆型号、城市、年限、里程和期望售价，筛选已有买车咨询。排除拒绝联系、暂无计划、已结束及预算/城市/车型不符的线索。买家未说明的车龄和里程接受度会明确标记待确认。
- 支持从需求文本预填、保存候选项、回看最近30次匹配。修改描述后直接匹配会先提取；手动修改的结构化筛选条件优先。
- 16辆独立合成车源，其中14辆在售、1辆已售、1辆预订。车型信息与价格用于演示，不是实时库存、真实行情或平台估价。
- `matching.py` 负责匹配，`web/matching.js` 负责买卖页面。当前为确定性条件匹配，尚未将车源工具接入模型循环。原有模型路径仍用于咨询画像提取。

验证：`python -m unittest discover -s tests -v` 现有33项测试；买卖浏览器脚本在 `tests/browser-matching.js`。

针对 AI 增长产品经理岗位制作的独立个人原型。用合成咨询验证从线索初筛到人工审核、跟进登记和来源复盘的流程；不是瓜子内部系统，也不使用其数据。

## 启动

只需要 Python 3.10+，不依赖第三方 Python 包或前端构建。

```powershell
Set-Location -LiteralPath 'D:\03_Development\Work\二手车\car-growth-agent'
python server.py --port 8765
```

打开 <http://127.0.0.1:8765>。也可在项目目录执行 `./start.ps1`。数据保存在本地 `data/leads.db`；重启保留分析、审核和跟进记录。服务默认只绑定本机，无登录，适合本地面试演示，不应直接开放到公网。

## 当前完成的能力

- 18 条合成咨询初始化，单条文本或 JSON/UTF-8 CSV 批量导入，相同姓名、渠道和原文去重。
- 规则模式提取城市、数字万元预算、购车时间和部分车型，并保留原文字符位置。
- 固定规则 A/B/C/D 分级：优先、待补充、低频培育、停止联系。规则分不是成交概率。
- 处理预算冲突、多城市、否定时间、首付/月供、拒绝联系及部分指令式输入。
- 草稿修改、负责人分配和人工审核；审核前不能跳到联系或成交。
- 联系 → 预约 → 成交/未转化的人工结果登记，每次保存审核或实际情况备注。
- 查询原文证据、处理轨迹、历史运行、状态操作记录，并导出 JSON。
- 来源和历史阶段去重统计；不预置联系、预约或成交成绩。
- 12 条保留合成案例的规则评估，输出逐条预期、结果、核验项和限制。
- 可选真实模型工具调用路径，API 未配置时明确提示，不将规则结果伪装成模型结果。

## 两种运行方式

### 规则演示（默认）

离线提取和规则分级，可重复、无需密钥。它是演示基线，并非大模型 Agent。在此模式下验证业务流程、审核状态与留痕。

### 模型 Agent（可选）

接入实现 OpenAI Responses API 的服务。运行前在本地 PowerShell 会话设置：

```powershell
$env:AGENT_API_BASE = 'https://api.openai.com/v1'
$env:AGENT_MODEL = '<你账户可用且支持工具调用的模型ID>'
$env:AGENT_API_KEY = '<在本机设置API密钥>'
python server.py --port 8765
```

不要把密钥放入简历、源码、截图或发到聊天里。程序只读取上述环境变量，不读取其他项目的 `.env`。界面不返回密钥。

注意：仅有 Chat Completions `/chat/completions` 接口的兼容服务不能直接使用；这里要求 `/responses` 及 `function_call`/`function_call_output` 协议。实际模型和服务支持情况需要配置后验证。

工具流程：`read_consultation` → `read_policy` → `submit_profile` → `create_followup_draft`。模型决定工具调用，服务端执行并返回结果。每项画像必须有逐字引文，预算和时间还需通过确定性校验；歧义回退为未知，由人工确认。工具白名单、顺序约束和最多8轮调用限制避免任意动作；模型无法通过人工审核，也没有发消息的工具。

失败记录原样标记为模型失败，不自动降级后声称模型成功。已有审核结果不能被新分析覆盖；版本号阻止旧页面覆盖新状态。模型模式逐条运行，以便观察工具轨迹和用量。

实现参考：[OpenAI 官方函数调用文档](https://developers.openai.com/api/docs/guides/function-calling)。本项目不绑定或推荐特定模型。

## 验证范围与局限

- 数据共30条，由人工编写；12条保留案例不是外部盲测。规则可能受到开发样例和测试过程影响，不能据此宣称真实线索准确率。
- 评估仅覆盖分级、城市、预算上限、购车时间及引文位置，不覆盖所有车型和任意复杂自然语言。
- 规则提取只支持列出的部分城市、车型和有限时间表达；中文数字预算、多轮改口、复杂否定及首付/车价混用仍需进一步完善。
- 模型提取采用保守校验，因此一些模型能理解而校验器不能理解的预算或时间表达会留空。这是首版限制，不是完整的通用语义验证。
- 单元测试中的模型响应为受控替身，用于核验协议调度和失败边界；未配置真实API时，不代表已经验证模型端到端效果。
- 跟进状态依赖人工登记。预约并非实际到店，没有触达平台、车辆库存、CRM或归因数据。
- 尚未测量人工处理时间、真实客户响应、转化率、获客成本或收入增量。规则耗时不能换算成这些业务结果。
- 首版没有自动发消息、营销内容生成、真实渠道接入或无人值守任务调度；聚焦一条线索处理闭环。
