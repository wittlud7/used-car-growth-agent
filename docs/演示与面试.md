1. 打开“咨询自动处理”，展示一批不同咨询的分流。可填6条公开验收案例，或选择咨询管理中的咨询；真实Agent和离线规则明确区分。
2. 找一条缺预算的咨询，补充客户实际回复，展示关联批次、沿用对话、重查车源，说明旧记录没有被覆盖。
3. 展示拒绝联系不会进入主动跟进；无匹配不会自行放宽；人工复核与失败仍需人处理。人工记录、真实预约和系统自动执行应分清。
4. 打开真实对照批次。此次直接模型与Agent均6/6通过，且直接模型更快、更省。明确承认：简单静态查询未证明需要Agent。业务价值来自批量执行、工具校验、上下文状态与人工处理记录。
5. 展示每条耗时、tokens、错误候选、工具轨迹。说明合成小样本与线上收益的距离；需要真实咨询、稳定客户ID、实时库存、人工计时及后续转化结果再验证。

可用的一句话：我把人工处理咨询拆成可执行步骤，并用相同输入对照直接模型；当前准确率没有差异，因此不夸大算法收益，先验证重复劳动能否被可靠承接。

本批次人工结果与原咨询审核流程分开保存；不会跳过原来的审核。新增批次输入不自动进入卖车匹配买家库。统一客户身份与CRM回写属于明确未完成的业务集成。

## v0.4 优先演示真实 Agent

1. 在Agent对话中先说“我想买车”，观察它追问城市和预算。
2. 补充“北京，预算十五万以内，想看卡罗拉，2020年以后，6万公里以内”，展开工具记录，展示模型调用 `update_requirements` 与 `search_vehicles`，核对实际车源卡片。
3. 要求“对比V001和V002”，展示 `compare_vehicles` 的工具结果与回复。
4. 要求“为V001生成看车待办”，说明此时只有确认卡，尚未建单。点击核对、填写负责人后，任务才进入本地队列。
5. 新建对话说“我要卖车，北京，2022年卡罗拉，3.2万公里，期望售价12.6万”，展示 `find_buyers`。

这部分已用真实DeepSeek API验证，原条件匹配仍作为工具底座和规则基线。讲清模型负责对话与工具选择，后端负责确定性筛选、证据核验和写操作确认。小规模合成验收不能说明真实成交增量。

## 三分钟演示

1. **问题（20秒）**：销售需要反复阅读咨询，整理城市、预算、车型和时间，再决定补问或安排跟进。缺信息和拒绝联系的情况不能与明确需求同等处理。
2. **流程（40秒）**：打开工作台，说明18条均是合成咨询；点击“批量分析”。选择林先生，展示提取信息、A级理由和原文证据。说明当前是规则基线，并没有调用大模型。
3. **行动（40秒）**：修改草稿并填写“模拟顾问”，通过审核；登记联系、预约或未转化，备注写“模拟演示结果”。展示操作记录。系统没有发送客户消息。
4. **失败与边界（30秒）**：选择首付/月供、多个城市或拒绝联系的案例，说明为何补问、为何停止联系。模型未配置时可以切换模型模式，展示明确的配置提示，不冒充模型已运行。
5. **结果验证（30秒）**：进入复盘与评估，看来源阶段统计及12条评估明细。解释保留案例是小型合成集，不代表真实线索质量或成交提升。
6. **模型路径（20秒）**：若已配置并实际跑通过API，再演示模型读取咨询和规则、提交证据画像、调用草稿工具的轨迹；否则仅解释已实现的接口与待验证部分。

## 面试官可能追问

**为什么使用 Agent，固定规则不够吗？**

规则负责稳定的分级、数值和状态；模型模式用于非标准文本的信息提取和工具编排。首版保留规则作为基线，不能仅凭架构断言Agent更好。下一步要收集更丰富的咨询，比较规则与模型在提取覆盖率、错误和人工修改上的差异。

**为什么不让模型直接决定高意向？**

优先级是运营政策，应可解释和版本化。服务端基于校验后的字段分级，拒绝联系等条件优先。模型的信心不能替代客户信息，也不能代表成交概率。

**到底替代了什么人工？**

首版覆盖信息整理、按规则初筛和草稿准备，人工仍需审核与业务沟通。目前未做真实人工计时，因此只能描述流程覆盖，不能说已减少某个百分比的人力。

**如何评价模型方案是否值得？**

按相同咨询比较人工、规则和模型：字段提取、拒绝联系识别、无证据内容、人工修改率、实际操作时间、调用成本和延迟。先证明减少操作且不损失质量，再在真实业务试用中验证响应和预约；增量成交需要更严谨的对照设计。

**你本人做了什么？**

如实说明AI协作开发。本人需要能讲清需求边界、分级政策、关键工具、数据流、状态限制、失败案例和测试；不要把尚未掌握的实现表述为独立手写。面试前亲自走完导入、审核、复盘及一次失败重试。
